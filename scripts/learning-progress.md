# 学习时间线维护

学习首页的 #progress 展示公开的每日进度。数据源为 data/learning_progress.json，模板为 layouts/partials/learning-progress.html，交互为 assets/js/learning-progress.js。

## 何时更新

按学习者要求，将更新进度作为检查阶段成果、整理每日笔记和发布笔记时的配套步骤。阅读最新代码、实际运行结果与当天对话后更新；不要只因文件修改时间变化就判定功能完成。网站不会自行读取本地源码或对话，也不凭日期增加打卡记录。

同一天同一项目更新原记录，进入新学习日才新增。日期以 Asia/Shanghai 的学习日期为准。课程日程不是完成进度，不按计划周数推算完成比例。

## 一条记录

- date：学习日期 YYYY-MM-DD。
- project：ops-ticket 或 student-management；新项目先加入 projects。
- title / summary：当天具体任务与已完成工作，使用面向读者的短句。
- verification：写清实际检查范围；跟写、经反馈修正、独立完成要按证据区分。
- next：当时下一步；旧记录按当日状态保留，不自动变成今天的待办。
- status：in-progress 表示学习中；当天笔记整理发布后改 reviewed，页面显示“当日已复盘”，不代表技能已掌握。
- note：已存在的当天笔记站内地址；笔记未发布时不添加。
- 顶层 updated：最新记录日期；stage：当前实际学习阶段；current_project：当前项目，用来选择顶部的下一步。
- 顶部统计记录条数，不推断连续打卡天数。同一天不同项目可以分别记录。

完成当天笔记后，在同一次博客提交中补上 note 并更新状态。先验证再发布：

~~~text
python scripts/validate_learning_progress.py
hugo --minify
~~~

同时核对筛选、较早记录展开、最新下一步、笔记链接和手机排版。无 JavaScript 时仍显示全部记录。数据校验已加入部署流程，避免重复记录或指向不存在的笔记。

## 当前基线

2026-10-06 至 10-11 来自学生管理系统六篇笔记；10-12 起属于设备运维工单新项目。10-16 的第四篇工单复盘覆盖 10-16 至 10-17 凌晨，按学习者要求统一记为 10-16，不另添空白日或跨夜记录。坏文件、空列表 Demo 与目录整理已完成，正式 JUnit 测试为 8 个（标题 6 个、文件存取 2 个），另有助手临时检查；已补齐第一周基础验收，并完成存档重复编号检查、Map 计数及恢复列表加入服务。当前主线仍是第二周，Maven/JUnit 属于提前接触的工具；自动接续编号、首次缺文件、坏数据的具体提示与完整重启验收尚待完成。旧记录及其当时的下一步保持原样，后续以当日记录和源码核对结果为准。

本时间线不统计未经记录的学习时长、不计算掌握率、不把助手的临时检查说成学习者编写了完整测试套件。

发布校验默认以 UTC+08:00 当前日期拒绝未来记录；需要重放某天检查时可传 --as-of YYYY-MM-DD。旧日尚未发布笔记的记录显示“当日记录”，避免长期显示为当前学习中。
