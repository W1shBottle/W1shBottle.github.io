## 现有成果与实际起点

当前是 Java 21＋Maven 的本地控制台项目，保留内存/文件仓库、菜单、17项JUnit和可运行JAR。2026-10-28环境已升级为MySQL8.4.13、Connector/J26.10.0；独立JdbcTicketQueryDemo已查询真实工单，支持状态参数、SQL NULL和方法提取。正式业务仓库未接数据库，Java更新事务、HTTP、登录权限、完整处理验收及AI/Agent仍待实现。

现有 Java 结构不算复杂，可继续用。需要改的是后续范围：旧计划把六表、评论、退回、看板及众多扩展排在 AI 前，现在将首版收敛为核心业务和必需工程能力，随即接入一个可评估的 AI 功能。

已有源码/运行结果不等于学习者独立掌握。SQL关联筛选、统计/分页、提交回滚和双连接版本竞争已有反馈；JDBC查询与方法提取是跟写、经解释修改后运行成功。助手执行的环境迁移与临时验证不计作学习者独立能力；以学习时间线和项目验收为准。

## 同一个项目的三个主阶段

| 阶段 | 交付范围 | 验收之后再做什么 |
| --- | --- | --- |
| A1 最小后端业务 | Java＋Spring Boot＋MyBatis＋MySQL，报修创建→派单→解决→验收关闭，详情/必要筛选 | 核心数据能持久化，能解释请求链；仍在本机教学 |
| A2 基础工程 | 会话认证、三角色与归属权限、参数与异常、事务日志、重复/并发请求、关键测试、部署排错 | 小版本可运行可部署，能独立改一项业务后进入 B |
| B 一个真实 AI 功能 | 结构化工单摘要、分类建议和待补充信息，用户决定是否采用 | API/结构校验/超时与错误降级可运行，真实调用有证据，进入 C |
| C 验证与改进 | 固定案例、无 AI 基线、内容质量、失败、延迟、用量和成本，改进后复验 | 用结果判断是否补 RAG、受控 Agent 或其他缺口 |

A1/A2 合在“Java 后端业务”主阶段中，分别对应最小业务与基础工程；评估从 B 首次调用就开始，C 专门整理并改进。Agent 不是必须从头做的第四个项目。按可检查的门槛推进，不承诺几周掌握；原 20 周文件名保留为教材索引。

## 第一版业务边界

设备来自虚构园区/实验室记录，无真实硬件连接。只保留三种角色：

| 角色 | 首版职责 | 不可越过的边界 |
| --- | --- | --- |
| REPORTER 报修人 | 选启用设备、创建、查自己的工单、验收 | 不能冒充别人报修、查询别人记录或自行派单 |
| ENGINEER 工程师 | 查分给自己的工单、提交非空处理说明 | 不能处理别人名下工单或代报修人验收 |
| ADMIN 管理员 | 查询、给 OPEN 工单指定启用工程师 | 不能随意设置状态或代报修人验收 |

流程为 OPEN→IN_PROGRESS→RESOLVED→CLOSED。首版不做验收退回、评论、公开注册、全套设备/用户后台、统计大屏。演示先用接口工具，随后可加简洁页面；不要求先学大型前端框架。

现有三表保留，A 阶段再加 ticket_action_log；处理说明存 resolve 动作 note，状态与日志同事务。暂不建 ticket_comment/ticket_resolution。创建重试用请求键，状态操作用前置状态＋期望版本；SQL 中 version 字段存在并不代表这些保护已实现。

具体规则、接口与验收不在本页重复维护，以项目 [需求](/learning/project-requirements/)、[设计](/learning/project-design/)、[验收](/learning/project-verification/) 为准。

## 第一项 AI 功能为什么这样选

工单经常只有杂乱描述。已有 title/description 就能支持“整理现象、给分类建议、指出缺的信息”，无需先做知识库或购置硬件。第一版对有权读取的工单返回 summary、category、missingInformation；category 限定 DISPLAY/PRINTING/HVAC/OTHER/UNKNOWN，只作为建议，不自动入库派单。首版只展示/复制参考，不直接写回标题。当前 rename 只有控制台和 Service 实现；以后要做人工采纳入口，先补明确权限、状态、版本和日志规则的 HTTP 接口。

这项功能能够练习真正的模型请求、响应结构、输入边界、成本和失败处理。AI 无依据时不编造型号/维修结论；模型不可用时正常报修、派单和验收继续运行。第一版不能声称故障诊断专家或自主维修 Agent。

B 开始前再选择供应商、模型与费用上限，准备本地环境变量；当前未配置或真实验证任何模型。Java 先实现清晰的 ModelClient 边界，调用 API，不强行拆 Python 服务。模拟响应只能验证解析与降级，不能充当真实模型效果。

## RAG 和 Agent 的加入条件

- 只有出现“需要根据手册给出处”的问题，才增加授权资料导入、来源版本、检索与引用；无相关依据时说明没有查到，记录召回和生成两种失败。
- 只有需要自然语言查询本人/授权范围内工单，才增加受控只读工具。工具复用 Service，程序校验权限和参数，不让模型拼任意 SQL。
- 只读工具稳定并有多步骤需求后，才加有限调用次数、上下文和失败处理。写入工具必须展示具体动作供确认，执行时重新检查权限/版本/参数，不能绕过 Java 业务规则。
- 不把 Redis、MQ、微服务、Kubernetes、MCP、多 Agent、本地训练或大规模向量库作为 AI 的先修课。

## 技术与学习方式

沿用 Java 21、Maven；当前MySQL8.4.13与Connector/J26.10.0已经过独立恢复和连接验证。先补短JDBC更新/回滚实验，再接Spring Boot＋MyBatis，不重复升级现有环境。框架版本到接入时按官方兼容表固定；认证仍优先Spring Security＋Session Cookie，保留CSRF并使用框架密码编码器。

两种 AI 学习分开：AI 辅助编程可用于解释/评审/排错，但每个模块要自己读调用链、独立改需求并验证；产品内 AI 功能则必须自己接入、测试真实 API 和失败路径。安排少量高价值测试，避免重复抄同类断言；数据库事务必须用真实 MySQL 验证，不能只看 Mock。

每次约 3 小时是时间预算，不是作业定额：先回忆已有代码，再讲一个新概念、独立写一个小变更、验证并记录帮助和困难。每个阶段至少独立实现/修改一个功能、解释一次设计、排查一个故障。完整任务见 [阶段学习计划](/learning/schedule/)。
