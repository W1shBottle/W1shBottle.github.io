## 第一版只做这些

报修人选择启用设备并填写报修 → 管理员派给启用工程师 → 该工程师提交处理说明 → 原报修人验收关闭；能查自己的列表和详情，管理员看全部。由 Java 判断角色、归属、状态、版本和字段；MySQL 持久化并提供约束。最小同源页面或 HTTP 客户端足以演示。

A2 补齐登录、校验、统一错误、事务、关键测试、可重复启动与一次排错后，即可进入 B。不先做评论、退回、附件、设备后台大全、缓存、消息队列、微服务或 Kubernetes。

B 只做已有工单摘要/分类建议：先授权读取已有工单，用户看完后审阅；模型不能直接改状态或派单。没有 API key、模型名称、可访问端点或预算时，先完成客户端契约和本地故障测试；结果标注“真实调用待配置”，不能用模拟响应声称 AI 验收通过。

## 每次学习的四件事

1. 说清这条业务需求需要什么知识，先读对应一两个类或 SQL。
2. 自己完成一个小修改；助手给提示、审阅或局部示例，不一次生成整套功能。
3. 运行一个正常场景和一个有价值的失败场景，记录预期与实际；已掌握的同质练习可跳过。
4. 关掉答案解释输入、调用链、数据库变化和失败路径，再做一个变体。

AI 辅助编程记录“工具帮了什么、我怎样确认”；项目 AI 记录“模型请求、结构化输出、失败降级、质量和成本”。两者不混为同一能力。

## 离线阅读与准备

可打开[连续阅读版](/learning/downloads/reader.html)，或[下载完整自学包](/learning/downloads/java-internship-self-study.zip)后解压，用浏览器打开 `reader.html`；包内Markdown可以独立阅读与记录。公开下载内容随课程同步更新，实际学习进度见[时间线](/learning/#progress)。

首次准备工具和依赖仍需网络；B阶段的真实模型调用需可用提供方、凭据与调用预算。未配置时可继续后端和本地契约测试，但明确记录“真实模型验证未完成”。遇到卡点先缩小为一条SQL、一个方法或一个请求，再查排错手册；按可投入时间调整选修范围。
