## 项目会做成什么

项目名为设备运维工单平台。使用者报修设备，管理员派给工程师，工程师记录处理过程，报修人验收或退回。最终交付设备管理、工单流转、分页筛选、三类角色权限、评论和操作记录、并发保护、测试、简易页面和部署说明。全程使用虚构数据，不需要实际设备。

```text
普通 Java 对象 → 集合与文件 → 数据库 → HTTP 接口
             → 权限与事务 → 并发测试 → 打包部署 → 求职演示
```

主要技术是 Java 21、Maven、Spring Boot 4.1 系列、Spring MVC、MyBatis、MySQL、Spring Security 和配套测试。开始时只用 Java；工具按阶段增加。知识库、缓存和 AI 都属于选做，核心没有通过验收时不加新组件。

## 每周怎样执行

1. 先看本周“成果”和“验收”，知道要做成什么。
2. 在这一周内自由安排任务，保留顺序依赖；例如先建表，再写 Mapper。
3. 一个任务通常包含理解、小步实现和验证，可以拆成几次学习。
4. 每次只修改一个能观察到结果的小点，及时保存和提交。
5. 独立回答本周自测题，再看对应参考答案。答案中的局部代码按说明补入自己的项目，不要把分散片段当成整套程序直接运行。
6. 周末按验收清单检查，写下一周的第一步。

各周任务表列出的小时数已经包含阅读、编码、基础练习和复盘，**不要在18小时之外再叠加额外的每日训练量**。可参考“2小时项目、45分钟基础或算法、15分钟复盘”的日内比例，但不必每天机械切换。

## 时间不够时如何调整

| 一周能投入 | 执行方式 |
| --- | --- |
| 15—18小时 | 正常完成本周必做任务；选做根据剩余时间决定 |
| 8—12小时 | 一周内容拆成两周，先做业务核心与验收，算法减量但不完全中断 |
| 少于8小时 | 保留两次短练习、一次复盘；记录停在什么地方，暂停开启新框架 |

日期只是准备窗口，顺序由前置能力决定。未通过核心验收就顺延，不能把“到下一周了”当成掌握。若连续两周落后，先删去看板美化、缓存、知识库和 AI；保留工单闭环、权限、数据一致性和交付。考试结束先用一次复盘恢复进度，不从头重学全部课程。

## 没有助手时怎样解决卡点

先花20—30分钟缩小问题：记下输入、预期、实际、第一条报错及根本原因；把相关逻辑缩成一个小方法或单条SQL。然后查本包的排错手册和对应周的答案，再查官方文档的准确类名或错误文字。

如果还是卡住，把任务缩小一级。例如“保存工单失败”先变成“写一行固定文字”，“登录后访问失败”先变成“查看登录请求、Cookie、CSRF和后续请求”。可以向同学、老师或技术社区展示最小复现和已经尝试的方法；这不需要购买服务。

不要为了把错误提示消掉而同时换 JDK、框架、数据库和依赖版本。先固定版本并改变一个因素，再观察结果。没有理解的参考实现记为“参考完成”，第二天关掉答案做一个小变体，能做出变体再记为独立掌握。

## 第一周从哪里开始

先能解释：`private` 控制访问，但不会自动检查数据范围；构造器和修改方法都需要执行校验，才能避免创建或修改出非法对象。

创建或打开 `ops-ticket` 普通 Java 项目，在 `src` 中创建 `Ticket.java` 与 `TicketDemo.java`。先写编号、标题、构造器和两个 getter，再创建两张工单观察数据互不覆盖。具体步骤见[第一课：工单对象与封装](/learning/first-ticket/)。

首次学习只完成第一课 A 步即可，不需要先阅读全部20周材料，也不需要当天配好数据库或框架。
