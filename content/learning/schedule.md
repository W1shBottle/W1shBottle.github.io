## A 阶段：Java 后端业务

A1 先形成最小闭环，A2 将它变成有权限、有故障边界且可交付的小版本。中间可以本机练习，但未完成登录与权限不能称作完整后端。

| 单元 | 先理解、阅读位置 | 亲手产出 | 验收与进阶门槛 |
| --- | --- | --- | --- |
| A0 SQL 收尾 | 现有 `sql/01_schema.sql`、`02_seed.sql`、`03_queries.sql`，复习列/值/NULL/LIKE/AND | 独立查询状态、报修人和关键词；预测命中与空结果 | 能说明 SELECT 不改状态、FK 不保证角色、CHECK 不代替授权 |
| A1.1 关联与事务 | 教材第5单元；查询 JOIN/LEFT JOIN、GROUP BY、固定排序；新建事务练习脚本时再落盘 | 列表显示设备/报修人/可空处理人；同连接 UPDATE 后 ROLLBACK/COMMIT | 未派单不丢失；知道 COUNT(t.id) 与 COUNT(*) 区别；实际确认回滚 |
| A1.2 短 JDBC | `pom.xml`、`Ticket.java`、`TicketRepository.java`；待建 `src/test/java/cn/wishbottle/opsticket/JdbcTicketQueryDemo.java` | PreparedStatement 先按id只读查询和SQL NULL映射，再在练习库做回滚更新；之后学习创建与生成ID | 单引号当普通数据、资源关闭、重启可读；不沿用 maxId+1 或假编号 |

## B 阶段：一个真实 AI 功能

第一功能为**已有工单描述的摘要和分类建议**：例如已有工单的description为“二楼空调开了很久仍不冷，还在滴水”，辅助整理简短摘要、建议类别和需补充的信息。内容不足就询问补充；不猜工程师、不写数据库、不自动决定处理状态；模型调用前必须先按原详情权限授权读取工单。

| 任务 | 先理解/预计位置 | 独立实现或修改 | 验收 |
| --- | --- | --- | --- |
| B1 模型客户端 | HTTP/JSON/超时；未来 `ai/ModelClient.java`、Java HttpClient、配置与客户端测试 | 先授权读取已有工单，再由Java调一次真实模型API；key由环境提供；解析受限结构 | 保存脱敏真实请求结果，模型与版本可追溯；API未配置写待验证 |
| B2 业务接入 | 未来 `ai/AiAssistanceService.java`、`POST /api/tickets/{id}/ai-assistance` | 先授权读取已有工单、限制上下文长度、校验结构字段/枚举/长度、展示建议 | AI 返回不能直接持久化；先检查工单访问权限，人工后续操作仍走普通业务校验 |
| B3 失败处理 | 请求超时、429/5xx、无效JSON、字段缺失；可控测试替身 | 有限调用时间/次数，降级提示和结构化日志；关闭AI仍可报修 | 模拟证明失败分支；真实调用证明服务可用，两类证据分别记录 |

模型调用放在数据库事务外，不拿着行锁等待网络。第一版无需 Python 服务或 Agent 框架；先使用一个模型提供方，选型在实际接入时核对可用性、协议、预算及数据范围。

## C 阶段：验证并迭代

固定一组输入作为对照集：正常明确、条件含糊、缺信息、无依据、长文本、中文标点、诱导越权、超时、限流、结构错误。每次记录预期、实际、人工评分、延迟、模型与提示词版本、tokens 和费用来源；无真实用量就写未知，不造成本数字。

至少比较“人工阅读已有描述后整理摘要”和“查看AI建议后人工修正摘要”的完成时间、修正次数或可用比例，说明样本规模和局限。把错误例子转成回归案例，再改提示词/输出约束/上下文，而不是随便换模型后只展示成功样本。可先用约20个案例建立基线，门槛在运行前约定；权限绕过、AI失败阻断主业务必须为0，质量类指标如实报告并说明是否适合展示。

## 可选升级：RAG 与受控 Agent

- **RAG**：仅在有可用运维资料且摘要功能不能解决知识问答时做。资料导入标明来源/版本/权限，切分、检索、引用可定位；查不到证据就回答不足，不补造结论。先关键词或简单检索，再判断是否需要向量库。
- **只读工具 Agent**：仅在自然语言查询需要组合业务数据时做。模型选择受控 `findVisibleTickets`/`getTicketDetail` 等工具，由 Java 从会话取身份、限范围与数量；不提供任意 SQL/URL 执行。限制步数、总耗时、上下文和调用预算，记录工具失败；一张只读查询能完成时不加多 Agent。
- **以后再考虑写工具**：明确参数预览和必要人工确认；确认之后仍重新鉴权、验证状态版本、防重复；不信任模型给出的操作者和授权结论。达到只读评估门槛前不做自动派单/验收。

## 下一批可直接执行的小任务

每项通常一次或几次学习即可完成，不强行塞入同一天。文件均相对 `项目根目录`，尚不存在的文件只在轮到该任务时创建。

1. **组合查询实操已通过**：学习者提交打印机＋OPEN＋IS NULL查询和实际结果：3／打印机卡纸／NULL／OPEN。解释、预测和排错可在下面关联变体中继续验证，不重抄这条成功语句。
2. **缺值与归属**：查 `assignee_id IS NULL`；加报修人条件。先 SELECT 当前数据，不重复插入早前“打印机卡纸”样本；空结果可以合法。解释 NULL 和字符串 `'NULL'`。
3. **列出业务规则**：对照 `sql/01_schema.sql`，口述 FK保证存在、CHECK保证单行组合；说明“禁用工程师/错误角色不能派单”还需Java。保存一段自己的解释。
4. **关联查询已跟练**：完整JOIN与OPEN变体已反馈成功，处理人为NULL的打印机工单保留；统计、HAVING和分页也已有结果。解释与独立变体沿后续任务巩固，不重抄全部语句。
5. **SQL事务已练习**：现有03_queries.sql/06_transactions.sql记录实验；用户已反馈提交/回滚及双连接A=1/B=0。旧version=0片段不是当前库的可重复初始化脚本。
6. **短 JDBC（当前）**：现有JdbcTicketQueryDemo已完成连接、参数查询、NULL和方法提取。下一次从executeUpdate与Java事务边界开始：单独写更新Demo，带当前版本修改一条练习工单，检查影响行数并显式回滚，再查询确认原标题与版本恢复。之后再学生成主键和HTTP，不提前加AI依赖。

## 学习节奏与展示

每周约 15—18 小时可拆为项目实现/排错、基础算法、简短复盘；忙时减少范围而非伪造完成。AI 可辅助找错和审阅，但每单元至少一次关闭答案的变体修改和一次调用链解释。测试围绕业务风险，不以断言数量衡量掌握。

原第1—6周材料对应A0/A1前半；第7—13周对应A1后半与A2身份；第14—17周的必要事务/测试/部署内容提前纳入A2；第18周性能与线程池按需；第19周原扩展不再作为AI起点；第20周项目表达随每个里程碑开展。求职不等待所有选修完成，第二份项目等首项目证据与实际岗位缺口明确后再决定。
